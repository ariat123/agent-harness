# Company discovery

Use the receiving team's established discovery executor. This portable skill describes the operating contract; it does not include a scraper or private tool installation. Read [Targeting](../../manual/01-targeting-and-lists.md) for downstream offer qualification.

## Define and plan

Establish company category, geography, requested scope, approved provider budget, contact expectations and historical deduplication source. Translate the request into the executor's supported configuration. Run an offline plan or validation before paid execution.

Do not add unsupported ownership, size, need or intent filters to a directory category. Source relevance and downstream offer fit are distinct judgments.

## Execute and preserve

Use a unique output location and the shared history registry. Obtain authorization for the actual paid execution and limits. Once approved, continue within that scope without repeating the same request for permission.

Let the executor own pagination, deduplication, extraction, retries, accounting and export. Use the live process handle while work runs. Diagnose concrete failures or invalid output rather than repeatedly reading unchanged results.

Preserve pending requests and unknown provider outcomes. Do not reset budgets or repeat uncertain billed requests to force completion. Resume the same authorized backlog; additional spending needs its own scope.

## Output

Return company records, people, email candidates, research gaps, backlog and the run summary as relevant. Inspect the validation result and explain coverage failures.

A public address is sourced; an inferred address is a candidate. Both remain mailbox-unverified until a separate provider result exists. Contact gaps do not authorize invented records or unrequested manual research. Apply account qualification through the separate evidence workflow before campaign use.

Discovery does not authorize verification or outreach. Never expose keys, headers or private account responses in a handoff.
